Where does the word "robot" come from? Not Greek or Latin, like automaton. It comes from the Czech robota, the forced labour a serf owed his landlord, and it reached the world through one play, Karel Čapek's R.U.R. of 1920. Čapek's drafts had called his manufactured workers labori. His brother Josef suggested roboti, and Karel kept saying the credit was Josef's. English picked the word up in 1922. #etymology #language

heh, just found a nice optimization that GCC does, that Clang doesn't: https://godbolt.org/z/ET1M34GzG

uint8_t returns87(uint8_t x) {
uint8_t product = 3 * x;
return product == 5 ? x : 87;
}

gcc optimizes this to "return 87", clang doesn't. this works because 3 is odd, hence no common divisors with 256. therefore multiplication by 3 is invertible mod 256, so GCC can compute what x must have been if 3 * x == 5 (namely 87).

I've been working on this since late 2023, and it's finally ready for everyone to use. The paint is still drying and I forgot to order enough ketchup, but everything works (and works really well). I'll be spending the weekend refining things further, though, especially the documentation.

What is DNS Kitchen? The simple (boring) answer is that it's an authoritative DNS hosting service. But the more interesting answer is that it's the result of me asking myself three questions a while back:

1. What would DNS management look like if it was *really* easy, for people who need some extra help with it?
2. What would it look like it was *really* nerdy, for power users who want to be as close to the metal as possible?
3. And, uh, could DNS ever be *fun*?

You can see it in action on the landing page and play around with stuff in the test kitchen. The "Just Text Chef" option is the easy mode. "I'll Have The Usual" is quite literally "the usual" form-based approach to DNS record management. (And no, Just Text Chef doesn't use any AI. Just PHP! You can read more about how Chef works under the hood here: https://dns.kitchen/docs/just-text-chef

I actually have a lot more to say about DNS Kitchen. And more plans for it! But this entry is already long enough as it is, so I'll save it for later. Maybe I'll make a video walkthrough. Anyway, I hope you enjoy it! Please feel free to share any feedback, as always.

A #Python string-literals gotcha I just ran into:

In a triple-quoted Python string, you can use the quote character if it appears once at a time:
"""a string with "quoted text" in it"""

But if you put a quote character at the _end_ of the string, that fails:
"""a string ending with "quoted text""""
because the _first_ three quotes of the final """" terminate the literal, and the fourth one is unmatched, and a syntax error.

Unless it's _not_ unmatched, because you had absentmindedly done this:
"""<a href="""" + html.escape(url) + """">link text</a>"""
so that there's an even number of extra " characters and they match again.

The meaning of this code from Python's point of view is three consecutive string literals, implicitly concatenated:
"""<a href=""" # triply-quoted
" + html.escape(url) + " # singly-quoted
""">link text</a>""" # triply-quoted
and the call to html.escape() in the middle, which was _supposed_ to be an actual function call, has silently become plain text, and you get no syntax error and a nonsense hyperlink.
